# 产品基础框架

`GM-Scout-Canvas` 是用于辅助线下桌游/跑团的数字地图与流程模拟工具。当前产品只保留通用桌游框架，不做小地图、雷达索敌、预设 NPC roster 或战术格子系统。

## 1. 地图面板编辑

大地图编辑功能对应真实桌游的地图面板：
- GM 导入一张背景图，通常是桌游地图、战役面板、区域图或场景图。
- 背景图只作为画布底图，不要求内建区域切片、网格或寻路。
- GM 可以在背景图上手动放置、移动、删除各种桌游配件。
- 配件可以表示棋子、标记物、建筑、资源、敌人、角色、事件点、状态 token 或任意自定义组件。
- 第一版只要求自由坐标放置；是否吸附、分层、锁定、旋转、缩放可作为后续扩展。

地图编辑器的核心不是模拟具体游戏规则，而是提供一个可操作的数字桌面。

## 2. 配件模型

配件是地图上的通用对象，不预设固定玩法类别。

建议最小字段：
- `id`: 稳定 id。
- `name`: 显示名称。
- `kind`: 自定义类型，例如 `token`、`marker`、`building`、`card`、`resource`。
- `position`: 画布坐标 `{ x, y }`。
- `appearance`: 颜色、图标、尺寸或图片引用。
- `state`: 当前状态字典，例如 `flipped`、`exhausted`、`hp`、`owner`。
- `notes`: GM 备注。

具体桌游的语义应由规则事件系统解释，不应硬编码在配件模型里。

## 3. 事件编辑

事件编辑功能对应桌游规则书中的流程规则。GM 可以预设游戏过程中什么时候触发什么。

事件至少包含：
- `trigger`: 触发条件，例如点击配件、移动配件、进入阶段、满足状态、手动触发。
- `conditions`: 额外条件，例如某配件在某位置、某状态值达到阈值、当前阶段匹配。
- `effects`: 触发效果，例如弹出剧情窗口、打开投骰判定窗口、修改配件状态、显示提示、推进阶段。
- `repeatable`: 是否可重复触发。

事件窗口不限定为剧情对话。它可以是：
- 剧情或说明文本。
- 投骰判定。
- 选择分支。
- 规则提示。
- 资源结算。
- 任意后续扩展的小游戏或表单。

## 4. 运行模拟

运行功能用于模拟桌游流程：
- Runner 加载 GM 编辑好的地图、配件和事件规则。
- 玩家或 GM 操作桌游配件，例如点击、移动、翻面、改状态。
- 系统根据预设规则判断是否触发事件。
- 触发后弹出对应窗口，并记录本次运行中的已触发事件和配件状态变化。

Runner 不应直接修改原始项目模板。运行状态应与编辑源数据分离，便于重开一局或保存一局运行记录。

## 5. 数据与存储

第一版继续使用 Save/Load JSON：
- 项目 JSON 保存背景图引用、配件列表、事件规则和基础元数据。
- 导入时校验 schemaVersion、配件引用和事件引用。
- 暂不引入 Supabase 或远端数据库。
- 未来如需要多设备同步、协作编辑或云端战役库，再增加存储适配层。

## 6. 明确砍掉的范围

以下内容不属于当前基础框架：
- 小地图和方形格子移动。
- 区域节点图和自动导航。
- 雷达索敌。
- 固定 NPC roster。
- 昼夜系统。
- A* 或战术移动。
- 内置具体桌游规则。

这些能力只有在后续具体游戏需求重新提出时，才作为插件或扩展进入任务清单。
