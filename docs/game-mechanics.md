# 游戏机制模型

本文件记录昼夜、导航与雷达的可测试规则。实现前如需调整规则，应先更新本文件和 `feature_list.json`。

## 昼夜系统

`globalTime` 至少支持 `Day`、`Night` 和后续可扩展的时间段。实体可声明 `appearanceTime`：
- `Always`: 任意时间可见。
- `Day`: 仅白天可见。
- `Night`: 仅夜晚可见。
- `Hidden`: 默认不可见，只能通过事件或雷达发现。

PixiJS 视觉滤镜只负责表现，不能作为可见性判断的事实来源。可见性必须由纯函数计算。

## 大地图导航

大地图导航基于节点图：
- 玩家当前位置是 `currentZoneId`。
- 相邻可达性由 `edges` 决定。
- 雷达或路径估算可以使用 edge hop 数作为图距离。
- 点击不可达 zone 时应返回明确的失败原因，而不是静默移动。

## 小地图移动

小地图移动基于方形格子：
- 基础移动使用四方向曼哈顿邻接。
- 被 building、障碍 tile 或地图边界占用的格子不可进入。
- 后续 A* 必须沿用同一套 `isCellWalkable` 判断。

## 雷达索敌

雷达应同时支持两种层级：
- 大地图：以 `currentZoneId` 为中心，按 edge hops 或 GM 配置半径扫描隐藏 zone/NPC 信号。
- 小地图：以玩家格子为中心，按曼哈顿距离或欧几里得距离扫描隐藏 NPC。

扫描结果应返回结构化数据：目标类型、目标 id、距离、提示文本、是否暴露精确位置。UI 只渲染结果，不重新计算命中逻辑。
