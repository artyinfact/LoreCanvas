# LoreCanvas 产品定义

`LoreCanvas` 是一款专为美式/叙事驱动桌游打造的戏剧化虚拟桌面引擎。它不是通用 3D 沙盒，也不是战棋网格编辑器；它的目标是让 GM 像在 CCFOLIA 中准备房间一样，把桌游剧本、地图、配件、规则提示和氛围演出预先编排好，运行时由玩家操作触发自动化反馈。

## 1. CCFOLIA 参考

CCFOLIA 的关键价值不是“复杂模拟”，而是降低 GM 的实时负担：提前准备房间、图片、面板、BGM 和场景切换，游玩时用少量操作展示信息、切换氛围、恢复初始盘面。LoreCanvas 借鉴这类体验，但把重点放在美式桌游常见的“地图节点、全局威胁、事件脚本、剧情演出”上。

需要保留的参考体验：
- 房间/剧本创建后，玩家可以打开并立即进入可操作的盘面。
- 面板和配件支持直观操作，玩家不需要理解内部脚本。
- GM 可以预设触发器，让移动、状态变化或手动指令自动弹出提示、剧情或演出。
- 运行中出现错误时，可以从剧本包或保存点恢复，而不是重新搭盘。

不照搬的部分：
- 不追求 CCFOLIA 的聊天、在线账号、商店、权限和 PRO 生态。
- 不以自由拖拽面板作为唯一抽象，核心地图采用 Node-Graph。
- 不把牌组、角色卡、参数栏等固定形态写死进引擎。

## 2. 核心概念

### Scenario Package

`.lorecanvas` 是可导入导出的剧本包，保存地图图谱、实体、全局追踪器、规则树、演出资源引用和基础元数据。它类似 CCFOLIA 的房间数据，但更强调可解析、可测试、可双向编辑的 JSON 结构。

### Board / Node-Graph

Board 可以引用任意 URL 或本地资源作为底图。底图之上是 Location 与 Edge 组成的 Node-Graph：
- `Location` 表示可被规则引用的位置，例如“夏尔”“布理”“魔多边境”。
- `Edge` 表示节点之间的连接关系，可用于移动校验或剧情判定。
- 坐标仅服务于渲染与交互，规则层以节点 id 为准。

核心中禁止引入 Grid、格子移动、A*、六边形、战术距离等网格假设。

### Entity

Entity 是所有可操作对象的统一模型：
- `id`: 稳定 id。
- `type`: 自定义类型，例如 `hero`、`threat`、`card`、`marker`、`objective`。
- `state`: 任意 JSON 字典，例如 `hp`、`faction`、`stealth`、`revealed`、`owner`。
- `locationId`: 当前绑定的 Location。

具体桌游语义由 `type`、`state` 和规则树解释，不在引擎里硬编码。

### Global Trackers

Global Trackers 表达全局数值或状态，例如 `Threat`、`Time`、`Sanity`、`Doom`。追踪器可以驱动规则，也可以通过视觉映射表改变盘面氛围，例如威胁升高时降低亮度、加深色调或叠加遮罩。

### Rule Trigger Engine

规则触发器以 JSON 形式描述：
- `trigger`: 事件来源，例如 `ENTITY_MOVE`、`ENTITY_STATE_CHANGE`、`TRACKER_CHANGE`、`MANUAL_TRIGGER`。
- `conditions`: 条件数组，例如属性比较、节点匹配、追踪器区间、实体类型匹配。
- `actions`: 动作数组，例如移动实体、修改追踪器、派发 Cut-in、显示规则提示。

引擎负责解析规则树并发射动作流。规则树必须可测试、可序列化、可由编辑器双向读写。

### Theatrical Cut-in

Cut-in 是 LoreCanvas 的演出层，对应 CCFOLIA 中“提前准备，一键展示”的体验。第一版重点支持：
- 遮罩与氛围滤镜。
- 图片或角色立绘滑入。
- 打字机文本。
- 规则提示窗口。
- 可由规则动作触发的演出 payload。

演出层只消费指令，不直接判断桌游规则。

## 3. Maker 与 Runner

Maker 用于 GM 准备剧本包：导入底图、创建节点、连接边、定义 Entity、配置全局追踪器、编写规则树和 Cut-in payload。

Runner 用于实际游玩或测试：加载 `.lorecanvas` 剧本包，创建独立运行状态，响应玩家操作并触发规则。Runner 不直接修改 Maker 源数据，这样同一剧本可以反复开局、回档或作为自动化测试输入。

## 4. LOTR 验收素材

`local-fixtures/lotr/` 保存 Tabletop Simulator 的 LOTR 模组脚本与图片素材，只作为本地阶段性验收输入。它不属于项目正式资产，也不能上传到 GitHub。

LOTR E2E 的目标不是把引擎变成 LOTR 专用模拟器，而是证明通用抽象足够表达复杂美式桌游流程，例如“戒灵拦截 -> 威胁追踪器变化 -> 视觉滤镜变深 -> Cut-in 演出”。

## 5. 非目标

当前核心不做：
- 在线账号、邀请链接、房间权限和商店。
- CCFOLIA 聊天系统或 BGM 管理。
- 网格地图、自动寻路、战术距离和小地图。
- 固定 NPC roster、固定牌组模型或固定角色卡结构。
- 具体桌游规则硬编码。
- 云端数据库、多人同步或商业发布流程。

这些能力只有在后续 feature 明确要求时，才作为插件或产品层扩展进入任务清单。
